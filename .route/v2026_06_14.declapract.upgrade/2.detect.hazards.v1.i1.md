## test hazards

### 1. slowtest reporter added to jest configs

**what changed**: `jest.unit.config.ts`, `jest.integration.config.ts`, `jest.acceptance.config.ts` now include:
```ts
['test-fns/slowtest.reporter.jest', { slow: '10s', output: '.log/slowtest/unit.report.json' }]
```

**why it may break**: if test-fns 1.15.8 does not export `slowtest.reporter.jest`, tests will fail to start.

**how to verify**: `rhx git.repo.test --what unit --mode apply`

### 2. test command shell evaluation changed

**what changed**: test commands in package.json changed from:
```
$([ -z $THOROUGH ] && echo '--changedSince=main')
```
to:
```
$([ "${THOROUGH:-}" != "true" ] && echo '--changedSince=main')
```

**why it may break**: different shell evaluation behavior. the new form requires `THOROUGH=true` explicitly, not just non-empty.

**how to verify**: `npm run test:unit` locally

### 3. @jest/globals added as dependency

**what changed**: `@jest/globals` 30.2.0 added to devDependencies.

**why it may break**: low risk. provides explicit imports for jest globals. may affect projects that don't use explicit imports.

**how to verify**: `rhx git.repo.test --what unit --mode apply`

## cicd hazards

### 4. test workflow restructured with sharding

**what changed**: `.github/workflows/.test.yml` now uses shard matrix for integration and acceptance tests:
- new `enshard` job generates shard matrix
- new `test-shards-integration` and `test-shards-acceptance` jobs
- new `test-shards-omit` placeholder job

**why it may break**: complex workflow change. however, test-shards-setup action handles absent shard config files gracefully (defaults to single shard).

**how to verify**: push to branch and verify CI passes

### 5. OIDC permissions added to test workflow

**what changed**: `test.yml` now includes:
```yaml
permissions:
  id-token: write # required for oidc
  contents: read
```

**why it may break**: low risk. enables OIDC auth. won't break if not used.

**how to verify**: CI workflow runs without permission errors

### 6. build step added before test:types

**what changed**: `.test.yml` now runs `npm run build` before `test:types`:
```
- name: build
  run: npm run build # build before test:types, to ensure .dist/ artifacts are importable for blackbox tests
```

**why it may break**: increases CI time. should not break anything.

**how to verify**: CI completes successfully

## config hazards

### 7. dpdm cycle detection added

**what changed**: new `.dpdmrc.yaml` file and `test:lint:cycles` command:
```
"test:lint:cycles": "dpdm --no-warning --no-tree --transform --exit-code circular:1 --exclude \"$(yq -r '.exclude | join(\"|\") // \"^$\"' .dpdmrc.yaml)\" 'src/**/!(*.test).ts'"
```

**why it may break**: if circular dependencies exist in the codebase, `npm run test:lint` will fail.

**how to verify**: `npm run test:lint`

## additional hazards (found on second scan)

### 11. tsconfig module resolution changed

**what changed**: `tsconfig.json` changed:
```json
- "module": "commonjs",
- "moduleResolution": "node",
+ "module": "node16",
+ "moduleResolution": "node16",
```

**why it may break**: node16 module resolution is stricter than node. may require file extensions in imports or break relative imports.

**how to verify**: `rhx git.repo.test --what types`

### 12. branch protection requires new CI context

**what changed**: `provision/github.repo/resources.ts` added new required context:
```ts
contexts: [
  'suite / install / pnpm',
  'suite / enshard',  // NEW
  ...
]
```

**why it may break**: branch protection will require `enshard` job to pass. if this job doesn't exist in workflow, merges will be blocked.

**how to verify**: push to branch and verify CI includes `enshard` job

### 13. github environments added

**what changed**: `provision/github.repo/resources.ts` added new environments:
- `envProductionOnMain` — production deployments from main (auto-approved)
- `envProductionOnElse` — production deployments from other branches (requires team approval)

**why it may break**: low risk for existing workflows. new environments may require `releasers` team to exist.

**how to verify**: `npm run provision` or push to trigger provision workflow
